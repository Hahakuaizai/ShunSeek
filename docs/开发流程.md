# 瞬觅 ShunSeek · 开发流程指导

> 产品一句话：不依赖 Everything 的 Windows 全盘搜索——热键呼出一个 DeskBox 式的小悬浮窗，
> 文件、文件夹、快捷方式、软件、安装目录、图片、视频等全部可搜、自动分类、毫秒级出结果。
>
> **第一性原则：搜索速度是核心。** 任何阶段加功能之前先问一句：它会不会拖慢
> 「呼出 → 输入 → 出结果」这条链路？会，就放后台、放缓存、或者不做。

整体架构（先建立全局图，再按阶段往下走）：

```
┌─ ShunSeek.App (WPF + WPF-UI) ────────────────┐
│  悬浮窗 / 热键 / 托盘 / 分类筛选 / 图标缓存     │
└──────────────▲───────────────────────────────┘
               │ SearchEngine.Search(query, 分类, limit)
┌─ ShunSeek.Core ──────────────────────────────┐
│  IndexStore（平坦内存索引，建好只读）          │
│  数据源: MftIndexSource / AppScanner /        │
│         DirectoryWalker / (UsnWatcher 增量)   │
└──────────────────────────────────────────────┘
```

## 阶段 0 · 环境与骨架

**目标**：工程能打开、基准能跑、空壳能弹窗。

**要做的事**
1. 装 Visual Studio 2022（勾选「.NET 桌面开发」工作负载）+ .NET 8 SDK。
2. 打开 `ShunSeek.sln`。先单独跑基准验证引擎：
   `dotnet run --project src/ShunSeek.Bench -c Release`
3. 再生成 `ShunSeek.App`（首次编译在 VS 里做；WPF 项目无法在 Linux 上构建，
   这是平台限制，不是工程问题）。NuGet 还原会自动拉 WPF-UI 3.0.5。
4. 运行 App：托盘出现图标，按 Alt+Space 呼出搜索窗，用演示数据试搜
   （试 `wzry` 应命中「王者荣耀.lnk」，试切分类 Chip）。

**验收标准**
- [ ] Bench 在你的机器上跑出完整数字（建索引 + 6 个查询耗时）。
- [ ] App 能弹窗/隐藏、能搜演示数据、Enter 能触发打开动作。

**常见坑**
- WPF + WinForms 同开时 `Application`、`MessageBox` 等类型名二义——代码里写全限定名。
- WPF-UI 的样式不生效：多半是 App.xaml 里 ThemesDictionary/ControlsDictionary 没合并。

## 阶段 1 · MFT 索引引擎（速度的地基）

**目标**：冷启动几秒内建好全盘索引，且内存可控。

**原理（必须懂，否则后面全是黑盒）**
- NTFS 的一切文件都登记在主文件表（MFT）里。`FSCTL_ENUM_USN_DATA` 能把
  USN 变更日志中现成的记录**成批**吐给用户态：一次调用返回约 1MB 记录，
  百万文件只要几十次调用、几次磁盘顺序读。这就是 Everything/WinShun
  「几秒扫完全盘」的全部秘密——它们不遍历目录，我们也不遍历。
- 每条 USN_RECORD 只有**文件名 + 本条引用号 + 父目录引用号**，没有全路径；
  全路径靠引用号父链拼出来（`MftIndexSource.ResolvePath` 已实现）。
- 索引只存内存（IndexStore 的平坦结构），不落盘、不建数据库文件——
  这是「点开即用、无需加载半天」的由来：重读 MFT 本来就只要几秒，
  没有值得预热加载的持久化状态。

**要做的事**
1. 在真机（管理员 PowerShell 里先验证）跑通 `MftEnumerator.EnumerateVolume('C')`，
   与 `fsutil usn` 的量级对一下条目数。
2. 把 `MftIndexSource` 接进 App 的启动流程（替换 DemoIndexSource），
   多卷（C/D/E…）逐个卷枚举后合并喂给 IndexBuilder。
3. **内存优化（重要）**：当前 IndexStore 给每条目存了 DisplayName + FullPath
   两个 string，200 万条目内存粗估约 400MB（Bench 可见），离验收线还差一截。两步压：
   - ① 目录前缀驻留：全路径拆成「目录串 + 文件名」，目录串去重成表存 int 下标
     （真实磁盘上目录数只有文件数的几十分之一，这一步砍掉大半）；
   - ② 原始大小写名也拼进 char 池（像 LowerName 那样），不再单独存 string。
   目标压到 200MB 以内后再进阶段 2。

**权限问题与两档方案（本阶段最关键的决策）**
读 USN/MFT 需要**管理员权限或卷访问权**，普通进程打开卷会得到 AccessDenied。
两档产品形态，二选一或都做：
- **方案 A（安装版，正解）**：装一个轻量 Windows 服务进程（管理员权限随系统启动），
  由它读 MFT/USN，通过**命名管道**把条目流喂给普通权限的 UI 进程。
  Everything 就是这个架构（Everything.exe 服务 + 前台）。好处：UI 不提权、
  开机即有索引；代价：要写服务、装/卸逻辑、管道协议。
- **方案 B（便携版，妥协）**：普通权限直接跑，只用 DirectoryWalker 索引
  「用户目录 + 开始菜单 + 用户指定文件夹」，不弹 UAC、解压即用；
  代价：搜不到全盘，只能搜圈定的范围（WinShun 的便携版就是类似取舍）。
- 建议顺序：先 B 跑通产品闭环，再做 A 补全盘能力。

**验收标准**
- [ ] 100 万+ 文件的机器上，全盘建索引 < 5 秒。
- [ ] 索引内存 < 200MB（优化后）。
- [ ] 无管理员权限启动时不崩，明确降级到方案 B 并在状态栏提示当前索引范围。

**常见坑**
- 引用号高 16 位是序列号，做 key 前必须掩码（代码里 FileRefMask 已处理）。
- 卷根目录引用号恒为 5、父指向自己，拼路径时要在此打住。
- $MFT 等 NTFS 元文件（引用号 < 16 的 $-开头记录）要过滤，不然结果里一堆系统垃圾。

## 阶段 2 · 搜索与排序

**目标**：按键到结果上屏 < 50ms（在阶段 1 的索引规模下）。

**要做的事**
1. 现状：`SearchEngine` 已是「分片并行 + Span.IndexOf 向量化扫描 + 打分排序」，
   Bench 里 200 万条目平均查询在本仓库的弱 VM 上是 26~127ms（见 README 的实测表），
   正常桌面 CPU 应在 10~40ms。先在自己机器上复测，再决定要不要进一步优化
   （如：高频查询结果缓存、按首字分桶预筛）。
2. 拼音：首字母已实现（GB2312 边界字表）。全拼是可选增强：需要拼音字典
   （如 Microsoft.International.Converters.PinYinConverter 或自备字表），
   索引体积会涨，默认不开，只在设置里给开关。
3. 结果上限与增量刷新：UI 只取前 100 条（已实现）；若以后要做「边扫边出」，
   注意结果跳动会打断键盘选择，增量批次要合并节流（≥100ms 一批）且保持已选项稳定。
4. **输入法 composing 保护（中文用户必踩）**：拼音输入法未上屏时，输入框里是
   组合串（如 "wang'zhe"），此时触发搜索会查出一堆垃圾还会闪烁。处理：
   - WPF 里监听 `TextCompositionManager.TextInputStart/TextInputUpdate` 或用
     imm32 的 `ImmGetCompositionString(GCS_COMPSTR)` 判断组合状态；
   - 组合中只更新输入框、不发查询；上屏（TextInput 事件）后才查。
   当前壳子只有 30ms 防抖，是占位，阶段 2 必须补上这一层。

**验收标准**
- [ ] 200 万条目下任意查询（Bench 同款查询集）< 30ms（桌面机）。
- [ ] 中文输入法连续打拼音过程中，结果列表不闪烁、不出中间态垃圾结果。
- [ ] 快速连续输入时旧查询被取消（CancellationToken 已接好，验证不串结果）。

**常见坑**
- 别在 UI 线程做扫描；别为了"实时"而去掉防抖直接每键一查（IME 场景必翻车）。
- 排序打分要克制：频次加分封顶，否则老文件霸榜、新装软件永远排不上来。

## 阶段 3 · 数据源补全与增量更新

> 状态（2026-11-21）：增量更新已落地——`DeltaIndex`（增量表 + 墓碑）+ `UsnWatcher`（USN）+
> `DirectoryUpdateWatcher`（FileSystemWatcher 兜底）+ `IndexService`（阈值/日志覆盖/目录改名
> 自动重建）。真机实测新建/改名/删除 < 1.2 秒反映到结果。机制说明见 README「索引与增量更新」。
> 仍待补：UWP 应用枚举、.lnk 目标解析。

**目标**：搜的范围 = 用户心里的"全盘"，且索引永远新鲜。

**要做的事**
1. `AppScanner` 已实现开始菜单/桌面快捷方式 + 注册表 Uninstall（软件与安装目录）。
   待补：UWP 应用（shell:AppsFolder 枚举，接入点注释在 AppScanner 末尾）、
   .lnk 目标解析（IShellLink，可选）。
2. `UsnWatcher` 骨架已给出（查询日志 + 阻塞读循环 + 记录解析）。
   落地增量合并：推荐「增量表」路线——新增/删除先进小表，SearchEngine 扫描时合并；
   累计变更超阈值或日志被覆盖（ERROR_JOURNAL_ENTRY_DELETED）时整卷重建（几秒，可接受）。
   改名是 OldName/NewName 成对事件，按 FileRef 配对，别当成一删一增。
3. 非 NTFS 卷（U 盘、exFAT）用 DirectoryWalker 兜底 + FileSystemWatcher 监听增量
   （Watcher 只适合小范围目录，全盘会丢事件，仅兜底用）。

**验收标准**
- [ ] 新装/卸载一个软件、桌面新建/删除一个文件，1 秒内反映到搜索结果。
- [ ] 搜软件名能出「应用」条目，点其安装目录条目能直达文件夹。
- [ ] U 盘插入后其文件可搜（兜底档即可），拔出后结果不残留。

**常见坑**
- USN 日志会被覆盖：起点太旧时 Read 直接报错，必须走重建分支，别硬重试。
- 注册表 Uninstall 有 64/32 位两个视图（WOW6432Node），漏一个就少一半软件。

## 阶段 4 · UI 打磨（对着 DeskBox 的完成度抠细节）

**目标**：好看、高级、跟手——小窗的每一帧都经得起看。

**要做的事**
1. 对着 `docs/ui-mockup.html` 调 XAML：间距、圆角、Mica 深浅、选中态，
   与目标稿逐项对齐；浅色主题补一套（跟随系统切换）。
2. **图标异步缓存**：IShellItemImageFactory 在后台按扩展名取图标、内存缓存，
   结果先占位后替换（接入点注释在 MainWindow.xaml.cs）。**红线：图标提取
   绝不进搜索/布局同步路径**——Shell 取图标可能访问网络路径，一次卡几十毫秒。
3. 命中高亮：按 SearchHit.MatchStart 把结果名切三段 Run，命中段加粗+主题色。
4. 键盘流：↑↓/PageUp/PageDown/Home/End、Enter 打开、Ctrl+Enter 定位、
   Ctrl+C 复制路径、右键菜单（打开/定位/复制路径/以管理员运行）。
5. 多显示器与 DPI：弹窗应出现在**鼠标所在屏**的上方居中（当前壳子用主屏工作区，
   待改）；不同缩放屏之间移动不糊（manifest 已声明 PerMonitorV2）。
6. 呼出速度：窗口与视觉树提前预热（DeskBox 的做法是空闲时预热弹窗壳），
   热键到上屏应 < 100ms；隐藏久了可释放视觉树省内存，呼出时重建。

**验收标准**
- [ ] 热键呼出无白闪、无布局跳动；连续呼出/隐藏 20 次不卡顿。
- [ ] 4K 150% 缩放与 1080p 100% 两块屏上位置、字号都正确。
- [ ] 结果图标滚动时不闪烁、不串行（虚拟化回收与异步图标的经典坑）。

**常见坑**
- ListBox 虚拟化 + 异步图标：行被回收复用时图标张冠李戴——绑定时校验路径再上图。
- 失焦隐藏与右键菜单/输入法候选窗打架：菜单打开期间要抑制失焦隐藏。

## 阶段 5 · 打包发布

**目标**：一个 exe 发出去，别人双击就能用。

**要做的事**
1. 发布：`dotnet publish src/ShunSeek.App -c Release -r win-x64 --self-contained true -p:PublishSingleFile=true`
   （自包含免装运行时；想再瘦身可试 Native AOT，但 WPF 对 AOT 支持有限，
   先用单文件自包含，别在这一步折腾）。
2. 开机自启：HKCU Run 项（托盘菜单开关已留 TODO 接入点）；安装版还要装阶段 1 的服务。
3. 崩溃日志：全局异常落盘到 %LocalAppData%\ShunSeek\logs，方便用户回传。
4. **未签名 exe 的预期管理**：没有代码签名证书时，SmartScreen 会拦、个别杀软会误报，
   这是独立小工具的常态（DeskBox 早期也一样）。README 里写清校验 SHA256 的方法；
   有余力再考虑 SignPath 等开源免费签名。
5. GitHub Release：版本号、更新日志、便携版 zip + 安装版（Inno Setup）双份。

**验收标准**
- [ ] 一台没装 .NET 的干净 Win10/11 虚拟机里，解压/安装后热键即用。
- [ ] 卸载干净：Run 项、服务、%LocalAppData% 数据按用户选择保留或清除。

## 附：与 Everything 的关键区别

| 维度 | Everything | 瞬觅 ShunSeek |
|---|---|---|
| 索引来源 | 自家服务读 MFT + USN | 同原理自建（MFT 直读 + USN 增量），**不依赖它的进程与 IPC** |
| 是否要装依赖 | 必须装 Everything 本体 | 单 exe 自包含，零依赖 |
| 索引持久化 | 落盘数据库，启动加载 | 纯内存，冷启动重读 MFT（秒级），无加载等待 |
| 搜索范围 | 文件/文件夹为主 | 文件/文件夹 + 快捷方式 + 软件 + 安装目录 + 分类筛选 |
| 中文支持 | 拼音需第三方增强 | 内置拼音首字母，开箱可搜 |
| 界面 | 传统列表窗 | DeskBox 式 Fluent 小悬浮窗，热键呼出 |
